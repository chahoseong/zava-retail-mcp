# 환경 구성

이 실습에서는 소매 분석 MCP 서버를 구현할 새 프로젝트를 준비합니다. 프로젝트 전용 Python 환경과 PostgreSQL 실행 환경을 구성하고, 이후 실습을 시작할 수 있는지 확인합니다.

이후 챕터에서는 같은 프로젝트에 데이터베이스 스키마, MCP 서버, 업무 도구와 시맨틱 검색을 차례로 추가합니다.

## 준비 사항

도구와 버전은 [소개 문서의 기술 스택](../00-Introduction/README.md)을 따릅니다.

- Git, `uv`, Docker와 Compose, VS Code를 준비합니다.
- Python은 `3.12+`를 사용하며, 프로젝트 실행 환경은 `uv`로 관리합니다.
- 임베딩은 로컬 EmbeddingGemma 2를 기본으로 사용합니다. Azure 서비스는 선택 기능으로 다룹니다.

## 프로젝트 구성

교육 저장소와 별도로 작업 디렉터리를 만들고 독립된 Git 저장소로 관리합니다. 프로젝트 이름은 `zava-retail-mcp`로 하겠습니다.

이번 실습에서는 다음 파일을 준비합니다.

| 파일 | 용도 |
| :--- | :--- |
| `pyproject.toml` | Python 요구 버전과 프로젝트 의존성 선언 |
| `.python-version` | 프로젝트에서 사용할 Python 버전 지정 |
| `uv.lock` | `uv`가 생성하는 의존성 잠금 파일 |
| `.gitignore` | 가상환경, 캐시, 로컬 비밀 설정 등을 버전 관리에서 제외 |
| `.env.example` | 필요한 환경 설정 항목과 예시 값 공유 |
| `compose.yaml` | 로컬 PostgreSQL 실행과 데이터 보존 구성 |

실제 접속 정보를 담는 `.env`는 로컬에 만들고 버전 관리에서 제외합니다. 가상환경과 잠금 파일은 `uv`로 생성하며, `uv.lock`은 직접 편집하지 않습니다.

## 진행할 작업

### 1. 작업 공간과 Python 환경 준비

- 새 프로젝트를 VS Code에서 엽니다.
- `uv`로 Python 프로젝트를 초기화하고, Python 요구 버전을 `3.12+`로 지정합니다.
- 프로젝트에서 사용할 Python 버전을 `.python-version`에 지정합니다.
- 소개 문서에서 정한 버전에 맞춰 공식 MCP SDK와 `asyncpg`, 개발·테스트 의존성을 `pyproject.toml`에 선언하고 설치합니다.
- `uv`로 프로젝트 가상환경과 `uv.lock`을 생성합니다.
- `.gitignore`에 가상환경, 캐시와 로컬 `.env`를 제외하도록 설정합니다.
- VS Code에서 프로젝트의 가상환경을 선택하고, 터미널과 편집기가 같은 Python 환경을 사용하는지 확인합니다.

### 2. PostgreSQL 실행 구성

- `compose.yaml`에 PostgreSQL 18과 pgvector를 사용할 수 있는 서비스를 정의합니다.
- 컨테이너를 다시 만들어도 데이터가 유지되도록 데이터 저장용 볼륨을 구성합니다.
- 접속 포트를 로컬 개발에 필요한 범위로 제한합니다.
- 이번 단계의 실행 대상은 PostgreSQL 서비스로 한정합니다.

소매 스키마, 샘플 데이터, 서비스용 DB 계정과 RLS 정책은 실습 04에서 구성합니다.

### 3. 연결 설정 구성

- DB 접속 주소, 포트, 데이터베이스 이름과 초기 접속 계정 정보를 정합니다.
- 필요한 설정 항목과 예시 값을 `.env.example`에 기록합니다.
- 실제 접속 정보와 비밀번호를 로컬 `.env`에 작성하고, 버전 관리에서 제외되어 있는지 확인합니다.
- Python의 DB 연결 확인에는 실행 중인 PostgreSQL과 일치하는 접속 설정을 사용합니다.

서버의 설정 로딩 코드는 MCP 서버 구현 단계에서 추가합니다.

## 완료 확인

다음 항목을 확인하고 결과를 기록합니다. 에이전트와 작업했다면 생성된 파일과 실행 결과를 함께 검토합니다.

- [ ] 프로젝트 Python 환경이 `3.12+`이며, `mcp`와 `asyncpg`를 불러올 수 있습니다.
- [ ] VS Code가 프로젝트의 Python 환경을 사용합니다.
- [ ] Compose로 PostgreSQL이 실행되고, pgvector가 설치 가능한 확장으로 제공됩니다.
- [ ] 준비한 접속 정보로 PostgreSQL에 연결하여 `SELECT 1`을 실행할 수 있습니다.
- [ ] `.env`와 가상환경은 Git 추적 대상에서 제외되고, 프로젝트 설정과 `uv.lock`은 저장소에 포함됩니다.

준비가 끝나면 현재 상태를 커밋합니다. 다음 챕터에서는 이 상태에서 데이터베이스 구현을 시작합니다.
